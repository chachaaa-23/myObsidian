### 1. WAF 연구 동향

기존 OWASP CRS를 기준으로, ML/AI 를 활용해 기존 방법보다 web application 기반 공격을 차단. 정규표현식, 수동으로 rule 및 수치 조정해야 하는 한계.

대체로 ML 활용하는 연구가 주를 이뤘음. 


<전통적 ML WAF>
Logistic Regression, Random Forest, SVM 등의 기법을 통해 request 들어왔을 때, 이것이 정상인지 악성인지(SQLi, XSS) 탐지, 분류.
	FP, 해석의 한계. 

참고 논문: 
1) Ai-Based Web Application Firewall (7th Feb 2025)
	ML 활용, Web Application의 SQLi, XSS 웹 기반 공격을 실시간 식별 및 차단하도록 함. 
	Logistic Regression, Random Forest, Support Vector Machine 사용
	backend에서 모델 평가, 쿼리 악성 여부 판단.
	https://ieeexplore.ieee.org/document/10928035/keywords#keywords	
2) AI‐Enabled Techniques for Assisting the Ensemble of Web Application Firewall and Rule‐Based Intrusion Detection System for Industry 5.0’s Applications (2025)
	ML 알고리즘 활용, web traffic 의 새로운 이상 징후 탐지, 자동으로 패치, 공격 경로 차단.
	WAF과 IDS(Intrusion Detection System, 침입 탐지 시스템) 통합. 
	https://ieeexplore.ieee.org/document/11081937	


<upgrade 1 ML WAF>
LLM을 활용해 능동적으로 payload 생성, 직접 WAF 우회해 봄, 결과 바탕으로 새로운 Ruleset 스스로 작성. 

참고 논문:
3)GenXSS: an AI-Driven Framework for Automated Detection of XSS Attacks in WAFs (25 Apr 2025)
	LLM 활용, XSS 대응 능력 강화 (GPT-4o 사용)
	 방어 메커니즘 자동화. 문맥 기반 학습으로 XSS payload 생성. WAF 공격 테스트, 우회 공격 분류, WAF 보안 규칙 생성. 
	https://arxiv.org/abs/2504.08176


<upgrade 2 ML WAF>
ModSec-Learn: Boosting ModSecurity with Machine Learning (19 Jun 2024)
	https://arxiv.org/pdf/2406.13547
ML 기반 CRS 규칙 가중치 선형적 학습, 탐지성능 극대화. 
(SQLi 중심)

HTTP request -> ModSecurity CRS -> Triggered Rule 추출 -> ML Model. 

ML
: 각각의 CRS Rule, 하나의 이진 feature vector 로 변환. (발생한 규칙 = 1, 발생x 규칙 = 0)
ML linear model (SVM, Logistic Regression), feature vector 입력받음, 어떤 규칙 조합이 실제 공격인지 가중치를 부여하며 학습.

-> 높은 Paranoia Level 에서도 TPR 상승 (FPR 1% 기준, 기존 ModSecurity 대비 TPR 45% 이상 향상. )
-> 기여도가 낮은 CRS Rule의 30% 이상을 시스템에서 제거함
	참고: [[OWASP WARM]]


=> 새로운 패턴에 강하지만 FP 높음 주의
=> 추후 AI Agent 로 Paranoia Level 과 같은 변수 세팅, FP rule 제거.
	ModSec-Learn 처럼 남은 CRS 규칙 가중치 학습으로 세부 조정하는 방식



### AutoResearch

실험, OpenClaw 기반 AI assistant가 오케스트레이션 역할, 데이터셋 구성 및 루프 등 관리. 
-> Claude Code 를 `--print` 모드로 (결과만 CLI에서 호출) 실험당 1회 호출.

다른 Ruleset 과의 차이점:
- 모든 공격 카테고리로 실험 (SQLi, XSS, RCe, LFI,...)
- threashold, Paranoia Level, content-type 등의 변수 조정
- 기존 CRS 규칙 제거
- custom 규칙 추가
- 쿠키/referer 헤더 제외
