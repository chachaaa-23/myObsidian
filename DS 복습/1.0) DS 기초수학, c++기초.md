## 기초 수학 background
알고리즘이 필요한 이유?
-> (직관적으로 떠오르는 방법으로는 대용량의 입격 값 커버 불가. )
"실행 시간(Time Complexity)"

**Exponential** 지수 함수 : 기하급수적 증가
**Log** 로그 함수 : 특정 y=a 직선으로 수렴. 지수함수의 역함수
Series 급수
-> 시간복잡도 분석 시 사용! (BST, Tree height 계산, ...)
	`O(log n)` `O(2^n)`

**Modular Arithmetic** 모듈러 계산법 : 나머지 연산
-> Hash Function 설계시 사용
	큰 수 계산 시 사용 (a * b)%m
	prevent overflow
	
**Prove Statement** : induction(귀납법. base case&assumption), contradiction(모순법), counterexample(반례)
-> 재귀함수의 참 증명시 사용
	알고리즘이 항상 동작함을 논리적 증명 시. 
		 Design rule(설계 법칙: 모든 재귀호출은 수행됨) 과 compound interest rule(복리 법칙: 중복 작업 x)

**Recursion** 재귀 함수 : 
"모든 계산은 함수 호출이 진행되는 경로를 따라가면서 컴퓨터에 의해 자동적으로 수행된다. "
(함수 호출은 재귀호출이 끝나길 기다리지 않고 시작된다. )
"순환오류에 빠지지 않도록, 초기값만을 통해 정의가 가능해야 한다."
-> DFS(Depth First Search: 깊이 우선 탐색), 백트래킹, sorting(merge, quick sort, ...), Tree 탐색 ( preorder / inorder / postorder : 왼쪽, 루트, 오른쪽 중에서 어디부터 찾을겨?)

## C++ 복습

**Class**
- = member 들로 구성. (member: 데이터나 함수로 구성) 
- class 의 **function** = member function = **method**

object
- = class로부터 생성된 instance

Lable (class member 의 visibility 결정)
- public
- private : 자신의 class 내 모든 method 에서 접근 가능. (주로 데이터 멤버를 private 으로 지정. )
-> 왜 이렇게 번거롭게 함? :  접근 제한을 통한 데이터 보호, 추후 유지보수 용이.

constructor
- class 의 instance 생성. 
- = 붕어빵틀 에서 팥과 반죽을 넣어서 붕어빵을 만든다. 
- 명시적으로 사용자가 만들지 않더라도 default constructor 자동 생성.
