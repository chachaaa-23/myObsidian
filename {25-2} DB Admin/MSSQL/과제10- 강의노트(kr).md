# MSSQL 파티셔닝(Partitioning) 정리

## 파티셔닝 소개

### 파티셔닝이란?

- MySQL과 유사하게 **수평 파티셔닝**(행 단위 분할) 지원
- 대용량 데이터셋의 성능 최적화 도구

### 파티셔닝의 장점

1. **파티션 제거(Partition Elimination) 메커니즘**
    - 쿼리 실행 시 필요한 파티션만 스캔
    - 전체 테이블이 아닌 관련 파티션만 검색하여 성능 향상

2. **I/O 부하 분산**    
    - 파티션을 서로 다른 파일 그룹에 할당
    - 여러 하드 드라이브에 분산하여 성능 향상

3. **다단계 데이터 저장**    
    - 최신 데이터: 고성능 디스크의 파일 그룹
    - 과거 데이터: 저성능 디스크의 파일 그룹
    - 클라이언트 관점에서는 동일한 테이블로 보임

### 파티셔닝의 단점
- 잘못된 파티셔닝 설계 시 오히려 성능 저하 발생 가능
- 파티셔닝 스키마 설계가 가장 큰 과제

## 기본 개념

### 1. 파티셔닝 키(Partitioning Key)

- 데이터를 파티션 간에 분할하는 데 사용되는 컬럼
- **사용 불가 타입**: `TEXT`, `NTEXT`, `IMAGE`, `XML`, `TIMESTAMP`, `VARCHAR(MAX)`, `NVARCHAR(MAX)`, `VARBINARY(MAX)`, CLR 사용자 타입, 별칭
- 테이블의 모든 인덱스도 이 키를 포함해야 함
- **선택 기준**: 쿼리에서 필터로 자주 사용되는 컬럼 선택

### 2. 파티셔닝 함수(Partitioning Function)

- SQL Server는 `RANGE` 방식만 제공
- 경계점(boundary points)을 기준으로 행 분류
- 경계점 개수 + 1 = 파티션 개수
- **예시**: `DATE` 타입 키에 경계점 2개 → 파티션 3개 생성
    - 첫 번째 경계점 이전 날짜 → 파티션 1
    - 경계점 사이 날짜 → 파티션 2
    - 두 번째 경계점 이후 날짜 → 파티션 3

### 3. 파티셔닝 스키마(Partitioning Scheme)

- 파티션을 파일 그룹에 할당
- 모든 파티션을 하나의 파일 그룹에 할당 가능
- 각 파티션을 서로 다른 파일 그룹에 할당 가능

### 4. 파티셔닝 계층 구조

```
파티셔닝 함수
    ↓
파티셔닝 스키마 (여러 개 가능)
    ↓
테이블 (여러 개 가능)
```

- 여러 테이블이 하나의 스키마 공유 가능
- 여러 스키마가 하나의 함수 공유 가능

## 파티셔닝 관리 실습

### 🩵1단계: 데이터베이스 준비

```sql
-- 데이터베이스 생성
USE MASTER;
CREATE DATABASE mssql10;

-- 🩵파일 그룹 4개 추가
ALTER DATABASE mssql10 ADD FILEGROUP FG1;
ALTER DATABASE mssql10 ADD FILEGROUP FG2;
ALTER DATABASE mssql10 ADD FILEGROUP FG3;
ALTER DATABASE mssql10 ADD FILEGROUP FG4;

-- 🩵각 파일 그룹에 파일 추가
ALTER DATABASE mssql10
ADD FILE
(
  NAME = 'mssql10_fg1',
  FILENAME = '/var/opt/mssql/data/mssql10_fg1.ndf'
)
TO FILEGROUP FG1;

-- FG2, FG3, FG4도 동일하게 추가...

-- 구성 확인
USE mssql10;
SELECT type_desc, name, physical_name, size, data_space_id
FROM sys.database_files
WHERE type_desc = 'ROWS';
```

### 🩵2단계: 파티셔닝 함수 생성

**시나리오**: 계좌 개설일(`otwarcie_konta`)을 기준으로 4개 파티션 생성

- 경계점: 1990-01-01, 2000-01-01, 2010-01-01

```sql
CREATE PARTITION FUNCTION fn_dekady_otwarcia (DATE)
AS RANGE LEFT  -- 경계값을 왼쪽 파티션에 포함
FOR VALUES
(
  '1990-01-01',
  '2000-01-01',
  '2010-01-01'
);
```

**RANGE 옵션**:

- `AS RANGE LEFT` (기본값): 경계값이 왼쪽 파티션에 포함
- `AS RANGE RIGHT`: 경계값이 오른쪽 파티션에 포함

**함수 확인**:

```sql
-- 🩵함수 목록
SELECT name, function_id, fanout, boundary_value_on_right
FROM sys.partition_functions;

-- 🩵경계점 확인
SELECT p.name, p.function_id, r.value
FROM sys.partition_range_values as r
JOIN sys.partition_functions as p
    ON r.function_id = p.function_id
WHERE p.name = 'fn_dekady_otwarcia';
```

- *`CAST` operator*
	: change data type [and length]
	`CAST(expression AS data_type [(length)])`

### 3단계: 파티셔닝 스키마 생성
```sql
CREATE PARTITION SCHEME partitioning_scheme
AS PARTITION partitioning_function
TO (FG1, FG2, FG3); -- 파티션을 파일 그룹에 순서대로 할당
```

**스키마 확인**:

```sql
SELECT * FROM sys.partition_schemes;
```

### 🩵4단계: 파티션된 테이블 생성

```sql
CREATE TABLE table_name (
  id              INT,
  ...
  imie            VARCHAR(50)
) ON partitioning_scheme_name(based_key_column);  -- 파티셔닝 키 지정
```

## `$PARTITION` 시스템 함수

### 🩵파티션별 행 수 확인

방법 1 (`$PARTITION` 함수 사용)
```sql
SELECT
  COUNT(*) AS 'Wiersze',  -- 행 수
  $PARTITION.fn_dekady_otwarcia(otwarcie_konta) AS 'Partycja' -- 파티션 번호 ( $PARTITION.파티션함수이름(테스트할_값_or_컬럼명) )
FROM bank
GROUP BY $PARTITION.fn_dekady_otwarcia(otwarcie_konta);
```

🩵방법2 ([`sys.partitions`](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-partitions-transact-sql?view=sql-server-ver17) 사용)

| Column name        | Data type  | Description                                                                                                                          |
| ------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `rows`             | **bigint** | Indicates the approximate number of rows in this partition.                                                                          |
| `partition_number` | **int**    | A 1-based partition number within the owning index or heap. For non-partitioned tables and indexes, the value of this column is `1`. |
| `partition_id`     | **bigint** | Indicates the partition ID. Unique within a database.                                                                                |
```sql
USE sklep;
SELECT 
    rows AS 'Wiersze',
    partition_number AS 'Partycja'
FROM sys.partitions
WHERE object_id = OBJECT_ID('table_name')
  AND index_id <= 1; -- 중복 데이터 방지
```

**결과 예시**:

```
+-----------+------------+
| Wiersze   | Partycja   |
|-----------+------------|
| 1         | 1          |
| 1         | 2          |
| 2         | 3          |
| 6         | 4          |
+-----------+------------+
```

### 파티셔닝 함수 시뮬레이션

새로운 파티셔닝 함수를 실제 적용 전에 테스트:

```sql
-- 테스트용 함수 생성 (2016년을 3개월 단위로 분할)
CREATE PARTITION FUNCTION fn_nowa_funkcja (DATE)
AS RANGE LEFT
FOR VALUES
(
  '2016-01-01',
  '2016-03-01',
  '2016-06-01',
  '2016-09-01',
  '2017-01-01'
);

-- 새 함수 적용 시 파티션 분포 확인
SELECT
  COUNT(*) AS 'Wiersze',
  $PARTITION.fn_nowa_funkcja(otwarcie_konta) AS 'Partycja'
FROM bank
GROUP BY $PARTITION.fn_nowa_funkcja(otwarcie_konta);
```

### 🩵특정 파티션 데이터 조회

```sql
-- 첫 번째 파티션의 모든 행 조회
SELECT *
FROM bank
WHERE $PARTITION.fn_dekady_otwarcia(otwarcie_konta) = 1;
```

**주의사항**:

- 테이블에 정의되지 않은 파티셔닝 함수 사용 시 메모리에서 실행
- 여러 네이티브 파티션을 동시에 사용할 수 있음
- 최적화되지 않아 서버에 부하 발생 가능

## 파티셔닝 수정

### 🩵범위 추가 (SPLIT)

**1단계: 새 파일 그룹 준비**

```sql
USE master;

ALTER DATABASE mssql10 ADD FILEGROUP FG5;

ALTER DATABASE mssql10
ADD FILE
(
  NAME = 'mssql10_fg5',
  FILENAME = '/var/opt/mssql/data/mssql10_fg5.ndf'
)
TO FILEGROUP FG5;
```

🩵**2단계: 스키마에 파일 그룹 할당**

```sql
USE mssql10;
ALTER PARTITION SCHEME s_dekady_otwarcia
NEXT USED FG5;  -- 다음 파티션이 FG5를 사용하도록 설정
```

🩵**파티션-파일그룹 매핑 확인**:

```sql
USE sklep; -- 검색할 DB 이동
SELECT ps.name AS 'NazwaSchematu', 
-- partitioning scheme 의 이름
	ds.name AS 'NazwaGrupy' 
	-- 파티셔닝 스키마와 매핑된 file group 의 실제이름(not id값)
FROM sys.partition_schemes AS ps 
-- partition scheme 정보 (partition scheme 이름& id 값 사용)
    JOIN sys.destination_data_spaces AS dds 
    -- partition scheme& file group id 정보 (파티션 스킴 id, file group id 값 사용해서 테이블끼리 매핑 도움)
        ON ps.data_space_id = dds.partition_scheme_id
        -- 같은 파티션 스키마 사용하도록 연동
    JOIN sys.data_spaces AS ds
    -- (파티셔닝 스키마 하위의)파일 그룹 정보 (파일 그룹의 string 이름값 사용)
        ON ds.data_space_id = dds.data_space_id;
        -- 검색하는 파티션 스키마의 파일 그룹 = 현재 찾는 파일 그룹 id 일치
```


🩵**3단계: 경계점 추가**

```sql
ALTER PARTITION FUNCTION fn_dekady_otwarcia()
SPLIT RANGE ('2017-01-01');
```

**결과 확인**:

```sql
SELECT
  COUNT(*) AS 'Wiersze',
  $PARTITION.fn_dekady_otwarcia(otwarcie_konta) AS 'Partycja'
FROM bank
GROUP BY $PARTITION.fn_dekady_otwarcia(otwarcie_konta);
```

### 🩵Remove boundary point (범위 병합 MERGE)

```sql
-- 2017-01-01 경계점 제거 (마지막 파티션 병합)
ALTER PARTITION FUNCTION fn_dekady_otwarcia()
MERGE RANGE ('2017-01-01');

-- 모든 경계점 제거 (모든 파티션 병합)
ALTER PARTITION FUNCTION fn_dekady_otwarcia() MERGE RANGE ('2010-01-01');
ALTER PARTITION FUNCTION fn_dekady_otwarcia() MERGE RANGE ('2000-01-01');
ALTER PARTITION FUNCTION fn_dekady_otwarcia() MERGE RANGE ('1990-01-01');
```

**주의사항**:

- 파티션 병합은 테이블 구조를 완전히 재구성
- 대용량 데이터셋에서는 매우 집약적인 작업
- 신중하게 사용해야 함

## 🩵파티셔닝 제거

### 순서
1. 테이블 삭제 (의존성 제거)
2. 파티셔닝 스키마 삭제
3. 파티셔닝 함수 삭제

```sql
-- 1. 테이블 삭제
DROP TABLE bank;

-- 2. 파티셔닝 스키마 삭제
DROP PARTITION SCHEME s_dekady_otwarcia;

-- 3. 파티셔닝 함수 삭제
DROP PARTITION FUNCTION fn_dekady_otwarcia;
```

## 핵심 요약

### 파티셔닝 구성 요소

1. **파티셔닝 키**: 데이터 분할 기준 컬럼
2. **파티셔닝 함수**: 경계점 정의 (경계점 N개 → 파티션 N+1개)
3. **파티셔닝 스키마**: 파티션-파일그룹 매핑
4. **파티션된 테이블**: 스키마와 파티셔닝 키 지정

### 주요 명령어

- `CREATE PARTITION FUNCTION`: 파티셔닝 함수 생성
- `CREATE PARTITION SCHEME`: 파티셔닝 스키마 생성
- `ALTER PARTITION FUNCTION ... SPLIT RANGE`: 파티션 추가
- `ALTER PARTITION FUNCTION ... MERGE RANGE`: 파티션 병합
- `$PARTITION`: 파티션 번호 확인 및 시뮬레이션

### 모범 사례

1. 쿼리에서 자주 사용되는 컬럼을 파티셔닝 키로 선택
2. 적절한 경계점 설정으로 균등한 데이터 분산
3. 파티션 제거 메커니즘 활용을 위한 WHERE 절 설계
4. 성능 테스트를 통한 파티셔닝 효과 검증
5. 대용량 작업(병합 등) 시 유지보수 시간 고려
