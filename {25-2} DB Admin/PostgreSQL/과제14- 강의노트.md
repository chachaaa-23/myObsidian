# PostgreSQL 테이블스페이스와 백업 정리

## 테이블스페이스(Tablespace)

### 🩵테이블스페이스 목록 확인

```sql
\db
```

```
         List of tablespaces
    Name    |  Owner   |  Location   
------------+----------+-------------
 pg_default | postgres | 
 pg_global  | postgres | 
 space1     | postgres | /srv/space1
```

### 기본 테이블스페이스

**클러스터 초기화 시 생성**:

|이름|용도|
|---|---|
|`pg_default`|기본 테이블스페이스, template1/template0 데이터베이스 소속|
|`pg_global`|시스템 카탈로그 저장용|

## 테이블스페이스에 객체 생성

### 데이터베이스 생성

**기본 DB (pg_default에 생성)**:

```sql
CREATE DATABASE 데이터베이스명;
```

🩵**특정 테이블스페이스에 DB생성**:

```sql
CREATE DATABASE company TABLESPACE space1;
-- owner 추가 시, create db-owner-tablespace 순으로 작성
```

🩵**확인**:

```sql
\l+
```

```
                                                                    List of databases
   Name    |  Owner   | Encoding |   Collate   |    Ctype    | Size   | Tablespace |
-----------+----------+----------+-------------+-------------+--------+------------+
 company   | postgres | UTF8     | en_US.UTF-8 | en_US.UTF-8 | 7693kB | space1     |
 postgres  | postgres | UTF8     | en_US.UTF-8 | en_US.UTF-8 | 7757kB | pg_default |
```

### 테이블 생성

**데이터베이스 전환**:

```sql
\c company
```

🩵**방법 1: TABLESPACE 절 사용**:

```sql
CREATE TABLE clients (id INT, name TEXT, surname TEXT) 
TABLESPACE pg_default;
```

**방법 2: default_tablespace 변수 설정**:

```sql
SET default_tablespace = pg_default;
```

- 이후 모든 `CREATE TABLE`, `CREATE INDEX`에 암시적으로 적용
- 빈 문자열이 아닌 값일 때만 동작

**🩵테이블 위치 확인**:

```sql
SELECT schemaname, tablename, tableowner, tablespace
FROM pg_tables
WHERE schemaname='public';
```

```
 schemaname | tablename | tableowner | tablespace 
------------+-----------+------------+------------
 public     | clients   | postgres   | pg_default
```

- `tablespace` 열이 비어있으면 데이터베이스의 기본 테이블스페이스 사용

## 테이블스페이스 권한

### 🩵역할 생성 및 테이블스페이스 생성

```sql
CREATE USER employee1;
CREATE USER employee2;

CREATE TABLESPACE space2 OWNER employee1 LOCATION '/srv/space2'; -- owner 생략 가능
```

### 🩵권한 부여

```sql
GRANT CREATE ON TABLESPACE space2 TO employee2;
-- tablespace: space2, role: emp2
```

**확인**:

```sql
\db+
```

```
                                      List of tablespaces
    Name    |   Owner   |  Location   |   Access privileges   | Size    
------------+-----------+-------------+-----------------------+---------
 pg_default | postgres  |             |                       | 23 MB   
 pg_global  | postgres  |             |                       | 590 kB  
 space1     | postgres  | /srv/space1 |                       | 7725 kB 
 space2     | employee1 | /srv/space2 | employee1=C/employee1+| 0 bytes 
            |           |             | employee2=C/employee1 |         
```

**권한 표기**:

- `C`: CREATE 권한
- `employee1=C/employee1`: employee1이 CREATE 권한 보유
- `employee2=C/employee1`: employee1이 employee2에게 부여

## 객체 이동

### 데이터베이스 이동

**주의**: 연결되지 않은 상태에서만 이동 가능

```sql
\c postgres
ALTER DATABASE company SET TABLESPACE space2;
```

**효과**:

- 데이터베이스의 기본 테이블스페이스 변경
- 원래 기본 공간에 있던 모든 테이블과 인덱스 이동

### 🩵테이블 이동

```sql
\c company
ALTER TABLE clients SET TABLESPACE space2;
```

- 인덱스도 동일한 방식으로 이동

## 테이블스페이스 삭제

```sql
ALTER DATABASE telemetry SET TABLESPACE pg_default;
-- big tablespace 가 위치한 DB인 telemetry 를 기본 tablespace 인 pg_default 로 옮김

DROP TABLESPACE space1;
```

**제약사항**:

- 삭제할 테이블스페이스에 객체가 없어야 함

## 백업(Backup)

### 백업 방법 3가지

|방법|설명|특징|
|---|---|---|
|SQL 덤프|논리적 복사|버전/아키텍처 독립적, 부분 복원 가능|
|파일 복사|물리적 복사|빠르지만 공간 많이 차지|
|지속적 아카이빙|WAL 기반|온라인 백업, 특정 시점 복구 가능|

## SQL 덤프

### 도구

**pg_dump**: 단일 데이터베이스 덤프 **pg_dumpall**: 클러스터 전체 덤프

### 🩵공통 매개변수

🩵**연결 옵션** (psql과 동일):

- `-h 서버주소`
- `-p 포트`
- `-U 역할이름`
- `-d DB이름`

🩵**덤프 범위 옵션**:

- `-n 스키마` / `--schema=스키마`: 특정 스키마만 (pg_dump만)
- `-t 테이블` / `--table=테이블`: 특정 테이블만 (pg_dump만)
- `-a` / `--data-only`: 데이터만 (객체 정의 제외)
- `-s` / `--schema-only`: 객체 정의만 (데이터 제외)
- `-g` / `--globals-only`: 전역 객체만 (pg_dumpall만)

🩵**복원 관련 옵션**:

- `-c` / `--clean`: 객체 재생성 전 DROP 명령 추가
- `--if-exists`: DROP 시 객체 없어도 오류 방지
- `-C` / `--create`: 데이터베이스 생성 포함 (pg_dump만)
- `-O` / `--no-owner`: 소유자 변경 명령 제외 (db owner 정보가 담긴 alter owner 문, 백업파일에서 삭제. 누구나 백업 파일 실행하도록 함)
	no commands changing the owner, useful if we are loading data without the superuser attribute
- `--inserts`: INSERT 문 사용 (다른 DB 이전 용이, 느림) (기본 COPY 방식 대신 INSERT 문으로 저장)

🩵**출력 옵션**:

- `-f 파일명`: 파일로 저장 (기본은 표준 출력)

예시1)
- make a copy of `users` table in `init_data` DB. 
  write data in the copy in `INSERT` commands
```shell
pg_dump -t users --inserts --no-owner init_data

```

예시2) 
- load a copy of the `users` table, saved in `users.sql` file into `telemetry` db.
```shell
psql -d telemetry -f users.sql
```

### 덤프 실행

**준비**:

```sql
INSERT INTO clients VALUES (1,'Ambroży','Zamojski');
```

**pg_dump 실행**:

```bash
$ sudo -u postgres pg_dump company
```

**출력 예시**:

```sql
--
-- PostgreSQL database dump
--

SET statement_timeout = 0;
SET lock_timeout = 0;
SET client_encoding = 'UTF8';

--
-- Name: clients; Type: TABLE; Schema: public; Owner: postgres
--

CREATE TABLE public.clients (
    id integer,
    name text,
    surname text
);

ALTER TABLE public.clients OWNER TO postgres;

--
-- Data for Name: clients; Type: TABLE DATA; Schema: public; Owner: postgres
--

COPY public.clients (id, name, surname) FROM stdin;
1	Ambroży	Zamojski
\.

--
-- PostgreSQL database dump complete
--
```

**덤프 구성 요소**:

- 주석 (`--`로 시작)
- 변수 설정
- 테이블 정의
- 소유자 설정
- 데이터 로딩 (`COPY` 명령)

### pg_dumpall 실행

```bash
$ sudo -u postgres pg_dumpall
```

**추가 포함 내용**:

```sql
CREATE ROLE employee1;
ALTER ROLE employee1 WITH NOSUPERUSER INHERIT ...;

CREATE TABLESPACE space2 OWNER employee1 LOCATION '/srv/space2';
GRANT ALL ON TABLESPACE space2 TO employee2;

CREATE DATABASE company WITH TEMPLATE = template0 ...;
```

- 역할 정의
- 테이블스페이스 정의
- 데이터베이스 정의

### 파일로 저장

```bash
$ sudo -iu postgres pg_dump -f /tmp/company.sql company
```

## 덤프 복원

### 3가지 방법

1. **배치 모드 (리다이렉션)**:

```bash
$ psql < file.sql
```

2. **-f 옵션**:

```bash
$ psql -f file.sql
```

3. **\i 내부 명령** (권장, 예제):
##### 🩵`\i` 명령어
- 외부 파일을 읽어서 현재 연결DB에서 실행하는 psql command
	`\i file_name.sql`

```bash
$ sudo -u postgres psql
```

```sql
CREATE DATABASE company2;
\c company2
\i /tmp/company.sql
```

**출력**:

```
SET
SET
...
CREATE TABLE
ALTER TABLE
COPY 1
```

**주의사항**:

- 첫 두 방법은 데이터베이스 이름을 psql 매개변수로 지정
- pg_dumpall 덤프는 여러 데이터베이스와 전환 명령 포함

## 기타 덤프 형식

### 형식 선택: -F 또는 --format

|형식|설명|
|---|---|
|`p` / `plain`|SQL 명령 텍스트 (기본값)|
|`c` / `custom`|압축된 바이너리 파일|
|`d` / `directory`|압축된 파일들의 디렉토리|
|`t` / `tar`|tar 아카이브 (압축 없음)|

### 복원 도구

**마지막 3가지 형식**: `pg_restore` 사용

**병렬 처리** (directory 형식):

```bash
$ pg_dump -F d -j 4 -f /backup/dir company
$ pg_restore -j 4 -d company2 /backup/dir
```

- `-j 개수` / `--jobs=개수`: 병렬 스레드 수
- 주의: `max_connections` 한도 초과 방지 (기본 100)

## 파일 백업

### 개념

**물리적 복사**: 데이터 파일 직접 복사

**장점**:

- 빠른 백업

**단점**:

- 더 많은 공간 사용 (인덱스 등 모든 내용 포함)

### 주의사항

**일관성 유지**:

- 모든 파일의 상태가 단일 시점에서 일치해야 함
- 클러스터 디렉토리 + 모든 테이블스페이스 포함
- 예: `/var/lib/postgresql/14/main`, `/srv/space2`

**방법 1: 서버 중지**:

- PostgreSQL 서버 완전 정지
- 파일 복사
- 서버 재시작

**방법 2: 파일시스템 스냅샷**:

- 서버 중지 없이 가능
- 단일 시점의 일관된 상태 보존
- **제약**: 여러 디스크의 동시 스냅샷 불가능할 수 있음

## 지속적 아카이빙(Continuous Archiving)

### WAL(Write Ahead Log) 개념

**기능**:

- 재해 복구용 로그
- 파일에 대한 모든 변경사항 기록
- 서버 재시작 시 마지막 체크포인트 이후 변경사항 재실행

**구조**:

- 세그먼트로 분할
- 번호가 증가하는 연속 파일
- 최신 체크포인트 이전 파일은 삭제됨

### 백업 방법

**구성 요소**:

1. **기본 복사**: `pg_basebackup` 도구 사용
2. **WAL 아카이빙**: 기본 복사 이후의 모든 WAL 파일 저장

### 설정

**postgresql.conf 수정**:

```ini
archive_mode = on
archive_command = 'test ! -f /mnt/server/archivedir/%f && cp %p /mnt/server/archivedir/%f'
```

**archive_command 설명**:

- `%p`: 복사할 로그 파일의 상대 경로
- `%f`: 해당 파일의 이름
- 실패 시 오류 코드 반환 (로그 파일 삭제 방지)
- 예시: 대상에 파일이 없으면 복사

### 복구 절차

1. **서버 중지**
2. **기본 복사 복원**
3. **recovery.conf 파일 생성**:

```ini
restore_command = 'cp /mnt/server/archivedir/%f %p'
```

4. **서버 시작**
    - 복구 모드 진입
    - 연속된 로그 파일의 변경사항 적용

### 고급 기능

**특정 시점 복구(Point-in-Time Recovery)**:

- recovery.conf의 추가 옵션 사용
- 특정 시간/트랜잭션까지 복구 가능

### 특징

**온라인 백업**:

- 서버 중지 없이 백업 가능
- 프로덕션 환경에 권장

**복잡성**:

- 설정과 관리가 복잡
- 추가 문서 숙지 권장

## 백업 방법 비교

|방법|장점|단점|용도|
|---|---|---|---|
|**SQL 덤프**|- 버전 독립적<br>- 부분 복원 가능<br>- 이식성 높음|- 느림<br>- 대용량 DB에 부적합|- 데이터 이전<br>- 부분 백업|
|**파일 복사**|- 빠른 백업<br>- 간단함|- 서버 중지 필요<br>- 공간 많이 차지|- 소규모 백업<br>- 간단한 복제|
|**지속적 아카이빙**|- 온라인 백업<br>- 특정 시점 복구<br>- 최소 데이터 손실|- 복잡한 설정<br>- 관리 부담|- 프로덕션 환경<br>- 미션 크리티컬 시스템|

## 핵심 요약

### 테이블스페이스

1. **목적**: 물리적 저장 위치 제어
2. **생성**: `CREATE TABLESPACE ... LOCATION '경로'`
3. **사용**: 데이터베이스/테이블 생성 시 `TABLESPACE` 절
4. **이동**: `ALTER DATABASE/TABLE ... SET TABLESPACE`
5. **삭제**: `DROP TABLESPACE` (객체 없어야 함)

### 백업 도구

1. **pg_dump**: 단일 DB 논리 백업
2. **pg_dumpall**: 전체 클러스터 논리 백업
3. **pg_basebackup**: 물리 백업 기본 복사
4. **pg_restore**: 압축 형식 덤프 복원

### 덤프 형식

1. **plain**: SQL 텍스트 (기본, psql로 복원)
2. **custom**: 압축 바이너리 (pg_restore)
3. **directory**: 병렬 처리 가능 (pg_restore)
4. **tar**: tar 아카이브 (pg_restore)

### 모범 사례

- **개발/테스트**: SQL 덤프
- **운영 환경**: 지속적 아카이빙
- **대용량 DB**: directory 형식 + 병렬 처리
- **정기 백업**: cron + pg_dump/pg_basebackup
- **재해 복구**: WAL 아카이빙 + 원격 저장소
