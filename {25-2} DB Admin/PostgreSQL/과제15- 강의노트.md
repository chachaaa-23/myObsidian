# PostgreSQL 파티셔닝 정리

## 파티셔닝 소개

### 파티셔닝 개념

**정의**: 논리적으로 단일 테이블로 보이는 데이터를 여러 물리적 부분(파티션)으로 분할

**PostgreSQL의 파티셔닝**: 수평 파티셔닝 지원 (전체 행을 서로 다른 파티션에 배치)

## 파티셔닝의 장점

1. **쿼리 성능 향상**
    - 자주 사용하는 행을 별도 파티션에 배치
    - 파티션별 인덱스 생성 → 작은 인덱스 → RAM에 적재 가능
2. **순차 접근 개선**
    - 대량 행 처리 시 파티션 내 순차 접근
    - 전체 테이블 무작위 접근보다 효율적
3. **빠른 데이터 삭제**
    - 파티션 전체 제거로 대량 데이터 삭제
    - 개별 행 삭제보다 훨씬 빠름
4. **저장소 최적화**
    - 자주 사용하는 행: 빠르고 비싼 디스크
    - 드물게 사용하는 행: 느리고 용량 큰 디스크
5. **파티션 프루닝(Partition Pruning)**
    - WHERE 절 조건에 따라 관련 파티션만 검색
    - 쿼리 최적화로 성능 향상

## 파티셔닝 전략
PostgreSQL이 제공하는 3가지 전략:

| 전략      | 설명                  |
| ------- | ------------------- |
| `LIST`  | 값 목록을 사용한 파티셔닝      |
| `RANGE` | 값 범위를 사용한 파티셔닝      |
| `HASH`  | 해시 함수 나머지를 사용한 파티셔닝 |

## 파티셔닝 키(Partitioning Key)
**정의**: 데이터를 파티션으로 분배할 때 고려되는 컬럼 또는 표현식 집합

**전략별 특징**:
- `LIST`: 단일 컬럼 또는 표현식
- `RANGE`, `HASH`: 여러 컬럼/표현식 가능

## 선언적 파티셔닝(Declarative Partitioning)
**도입**: PostgreSQL 10부터 지원
**이전 버전**: 상속, 함수, 트리거 사용 (여기서는 다루지 않음)

## 파티셔닝 구현

### 기본 구조
1. **마스터 테이블**: 파티셔닝 전략 및 키 정의
2. **파티션 테이블들**: 실제 데이터 저장
3. **마스터 테이블은 비어있음**: 모든 행은 파티션으로 전달

**중요**: 파티션 조건에 맞지 않는 행 추가 시 오류 발생

## LIST 전략 파티셔닝
### 🩵마스터 테이블 생성

```sql
CREATE TABLE products1 (
    id int,
    category_id int,
    subcategory_id INT,
    name TEXT,
    added DATE
) PARTITION BY LIST (category_id);
-- LIST 대신 RANGE, HASH 대입 가능
```

### 🩵파티션 생성

```sql
-- 가구 파티션 (카테고리 1, 2)
CREATE TABLE products1_meble 
PARTITION OF products1 
FOR VALUES IN (1, 2);

-- 액세서리 파티션 (카테고리 3, 5, 6)
CREATE TABLE products1_akcesoria 
PARTITION OF products1
FOR VALUES IN (3, 5, 6);
```

**특징**:

- 컬럼 정의 불필요 (마스터 테이블에서 상속)
- 특정 값 목록 지정

### 데이터 삽입 및 조회

```sql
INSERT INTO products1 VALUES (1,1,1,'krzesło','2019-03-12');
INSERT INTO products1 VALUES (2,3,1,'wazon','2019-08-19');
```

**마스터 테이블 조회** (모든 파티션 데이터):

```sql
SELECT * FROM products1;
```

```
 id | category_id | subcategory_id |  name   |   added    
----+-------------+----------------+---------+------------
  1 |           1 |              1 | krzesło | 2019-03-12
  2 |           3 |              1 | wazon   | 2019-08-19
```

**개별 파티션 조회**:

```sql
SELECT * FROM products1_meble;
```

```
 id | category_id | subcategory_id |  name   |   added    
----+-------------+----------------+---------+------------
  1 |           1 |              1 | krzesło | 2019-03-12
```

### NULL 값 지원

**LIST 전략만 가능**: 파티션 조건에 `NULL` 값 사용 가능

## 🩵서브파티셔닝(Subpartitioning)

### 개념

- LIST 전략은 다중 컬럼 키 미지원
- 서브파티셔닝으로 파티션을 더 세분화

*why use?*
- 데이터 분산: 한 개의 파티션 테이블에 데이터가 많아서 성능 저하 우려 시

### 예제

```sql
-- 조명 파티션 생성 (서브파티셔닝)
CREATE TABLE products1_lampy
PARTITION OF products1
FOR VALUES IN (4)
PARTITION BY LIST (subcategory_id);

-- 천장 조명 서브파티션
CREATE TABLE products1_lampy_sufitowe
PARTITION OF products1_lampy
FOR VALUES IN (1);

-- 책상 조명 서브파티션
CREATE TABLE products1_lampy_biurkowe
PARTITION OF products1_lampy
FOR VALUES IN (2);
```

**특징**:

- 파티션 내에 추가 파티셔닝
- 서브파티션은 다른 전략 사용 가능

## RANGE 전략 파티셔닝

### 🩵마스터 테이블 생성

```sql
CREATE TABLE products2 (
    id int,
    category_id int,
    subcategory_id INT,
    name TEXT,
    added DATE
) PARTITION BY RANGE (added);
```

### 🩵파티션 생성

```sql
-- 2018년 제품
CREATE TABLE products2_2018
PARTITION OF products2
FOR VALUES FROM ('2018-01-01') TO ('2019-01-01');

-- 2019년 제품
CREATE TABLE products2_2019
PARTITION OF products2
FOR VALUES FROM ('2019-01-01') TO ('2020-01-01');
```

**범위 규칙**:

- **포함**: 시작 값 이상 (`>=`)
- **제외**: 종료 값 미만 (`<`)
- 예: `2019-01-01`은 `products2_2019`에 포함

## 🩵MINVALUE와 MAXVALUE

### 🩵무한 범위 지정

```sql
-- 2018년 이전 모든 제품
CREATE TABLE products2_old
PARTITION OF products2
FOR VALUES FROM (MINVALUE) TO ('2018-01-01');
-- TABLESPACE t_space_name 추가 가능
```

- `MINVALUE`: 최소값 무제한
- `MAXVALUE`: 최대값 무제한

## 🩵DEFAULT 파티션

### 문제 상황

```sql
INSERT INTO products2 VALUES (3,1,1,'fotel','2020-05-30');
```

```
ERROR: no partition of relation "products2" found for row
DETAIL: Partition key of the failing row contains (added) = (2020-05-30).
```

### 🩵해결: DEFAULT 파티션 생성

```sql
CREATE TABLE products2_default
PARTITION OF products2
DEFAULT;
```

**효과**: 조건에 맞지 않는 모든 행 수용

```sql
INSERT INTO products2 VALUES (3,1,1,'fotel','2020-05-30');
-- 성공

SELECT * FROM products2_default;
```

```
 id | category_id | subcategory_id | name  |   added    
----+-------------+----------------+-------+------------
  3 |           1 |              1 | fotel | 2020-05-30
```

## 🩵HASH 전략 파티셔닝

### 개념
- 해시 함수 결과 기반 데이터 분배
- 다양한 데이터 → 파티션 간 균등 분산
- 여러 하드 드라이브에 부하 분산

### 마스터 테이블 생성
```sql
CREATE TABLE products3 (
    id int,
    category_id int,
    subcategory_id INT,
    name TEXT,
    added DATE
) PARTITION BY HASH (id);
```

### 파티션 생성 매개변수

**MODULUS (나누는 수)**:
- 해시 함수 결과를 나눌 수
- 보통 **파티션 개수**와 동일

**REMAINDER (나머지)**:
- 나눗셈의 나머지
- **행**을 특정 파티션에 **할당**

- 마스터 테이블: 데이터가 실제로 저장되진 않는 가상의 틀
- 자식 테이블: `CREATE TABLE` 명령어로 만들어지는 실제 데이터 저장 공간

🩵`CREATE TABLE table_partition_name PARTITION OF master_table_name FOR VALUES WITH (MODULUS n, REMAINDER m)`
- n: 몇 개의 파티션으로 만들건지?
- m: 몇 번째 파티션인지?

### 🩵
예제 (3개 파티션)

```sql
-- 나머지 0
CREATE TABLE products3_part1
PARTITION OF products3
FOR VALUES WITH (MODULUS 3, REMAINDER 0);

-- 나머지 1 (space3에 배치)
CREATE TABLE products3_part2
PARTITION OF products3
FOR VALUES WITH (MODULUS 3, REMAINDER 1)
TABLESPACE space3;

-- 나머지 2 (space4에 배치)
CREATE TABLE products3_part3
PARTITION OF products3
FOR VALUES WITH (MODULUS 3, REMAINDER 2)
TABLESPACE space4;
```

**NULL 처리**: 항상 `REMAINDER 0` 파티션으로 이동

## 🩵파티션 분리(DETACH)

### 개념
- 데이터 보존하면서 파티션 분리
- 파티션이 일반 테이블로 전환

### 예제
```sql
ALTER TABLE products1 DETACH PARTITION products1_akcesoria;
-- products1_akcesoria : partition name
```

**결과**:

- `products1_akcesoria` 테이블은 존재하고 데이터 유지
- 마스터 테이블 목록에서 제거
- 마스터 테이블 조회 시 해당 데이터 제외

```sql
SELECT * FROM products1_akcesoria;
```

```
 id | category_id | subcategory_id | name  |   added    
----+-------------+----------------+-------+------------
  2 |           3 |              1 | wazon | 2019-08-19
```

```sql
SELECT * FROM products1;
```

```
 id | category_id | subcategory_id |  name   |   added    
----+-------------+----------------+---------+------------
  1 |           1 |              1 | krzesło | 2019-03-12
```

**용도**: 아카이브 목적으로 데이터 보존하면서 성능 향상

## 파티션 연결(ATTACH)

### 기존 테이블을 파티션으로 추가

**준비**: LIKE를 사용한 테이블 생성

```sql
CREATE TABLE products1_dywany (
    LIKE products1
    INCLUDING DEFAULTS
    INCLUDING CONSTRAINTS
);
```

**데이터 추가**:

```sql
INSERT INTO products1_dywany VALUES (4, 10, 1, 'dywan_welurowy', '2018-11-13');
```

**파티션으로 연결**:

```sql
ALTER TABLE products1
ATTACH PARTITION products1_dywany
FOR VALUES IN (10);
```

**결과 확인**:

```sql
SELECT * FROM products1;
```

```
 id | category_id | subcategory_id |      name      |   added    
----+-------------+----------------+----------------+------------
  1 |           1 |              1 | krzesło        | 2019-03-12
  4 |          10 |              1 | dywan_welurowy | 2018-11-13
```

**요구사항**:

- 연결할 테이블의 컬럼이 마스터 테이블과 동일해야 함
- `LIKE` 절로 테이블 구조 복사 권장

## 핵심 요약

### 파티셔닝 전략 비교

| 전략        | 용도          | 키 특징      | 특수 기능             |
| --------- | ----------- | --------- | ----------------- |
| **LIST**  | 명확한 카테고리 분류 | 단일 컬럼/표현식 | NULL 값 허용         |
| **RANGE** | 날짜, 숫자 범위   | 다중 컬럼 가능  | MINVALUE/MAXVALUE |
| **HASH**  | 균등 분산       | 다중 컬럼 가능  | MODULUS/REMAINDER |

### 파티션 관리 명령

|작업|명령|효과|
|---|---|---|
|**생성**|`CREATE TABLE ... PARTITION OF`|새 파티션 추가|
|**삭제**|`DROP TABLE 파티션명`|파티션과 데이터 삭제|
|**분리**|`ALTER TABLE ... DETACH PARTITION`|데이터 보존, 파티션 해제|
|**연결**|`ALTER TABLE ... ATTACH PARTITION`|기존 테이블을 파티션으로|

### 고급 기능

1. **서브파티셔닝**: 파티션 내 추가 파티셔닝
2. **DEFAULT 파티션**: 조건 불일치 행 처리
3. **테이블스페이스**: 파티션별 물리 위치 지정
4. **파티션 프루닝**: 자동 쿼리 최적화

### 모범 사례

1. **전략 선택**:
    
    - 명확한 카테고리 → LIST
    - 시간/날짜 데이터 → RANGE
    - 균등 분산 필요 → HASH
2. **성능 최적화**:
    
    - 자주 조회하는 파티션: 빠른 디스크
    - 아카이브 파티션: 저렴한 대용량 디스크
3. **유지보수**:
    
    - 오래된 데이터: DETACH로 아카이브
    - 새 기간 데이터: 정기적으로 파티션 추가
    - DEFAULT 파티션: 예외 상황 처리
4. **쿼리 작성**:
    
    - WHERE 절에 파티션 키 포함
    - 파티션 프루닝 활용
