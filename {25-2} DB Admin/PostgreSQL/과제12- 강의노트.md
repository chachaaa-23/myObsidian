# PostgreSQL 역할, 속성, 인증, 권한 정리

## PostgreSQL의 역할(Role) 개념

### 역할이란?

- **역할**: `사용자(user)`와 `그룹(group)` 개념의 결합
    - 로그인 권한이 있으면 → 사용자에 가까움
    - 로그인 권한이 없으면 → 그룹에 가까움

### 역할의 기능

- 객체(테이블, 함수 등) 소유
- 객체에 대한 권한 보유
- 추가 속성 보유
- 다른 역할을 그룹화하여 권한 부여

### 연결

```bash
$ sudo -u postgres psql
```

## 역할 조회 및 관리

### 역할 목록 확인

```sql
postgres=# \du
```

**출력 예시**:

```
                                   List of roles
 Role name |                         Attributes                         | Member of 
-----------+------------------------------------------------------------+-----------
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS | {}
```

### 현재 역할 확인

```sql
SELECT CURRENT_USER;
```

### 역할 저장 위치

- **시스템 카탈로그**: `pg_authid` 테이블
- **주의**: 직접 수정 금지, SQL 명령 사용

**테이블 구조 확인**:

```sql
postgres=# \d pg_authid
```

**비밀번호 가려진 뷰**:

```sql
SELECT rolname, rolpassword FROM pg_roles WHERE rolname='postgres';
```

```
 rolname  | rolpassword 
----------+-------------
 postgres | ********
```

## 역할 속성(Role Attributes)

### 🩵주요 속성

|속성|설명|
|---|---|
|`LOGIN`|서버 연결 권한|
|`SUPERUSER`|모든 권한 (로그인 제외)|
|`CREATEDB`|데이터베이스 생성 권한|
|`CREATEROLE`|역할 생성 권한|
|`REPLICATION`|서버 간 데이터베이스 동기화 시작 권한|
|`INHERIT`|다른 역할로부터 권한 상속 가능|
|`BYPASSRLS`|행 보안 정책 우회 권한|
|`PASSWORD`|비밀번호 설정|

### 기본 속성

- 새 역할: 기본적으로 `INHERIT`만 활성화
- 다른 속성: 명시적으로 지정 필요
- 상속 비활성화: `NOINHERIT` 지정

### 속성 상세 확인

**수직 표시 모드**:

```sql
\x
Expanded display is on.
```

```sql
SELECT * FROM pg_roles WHERE rolname='postgres';
```

```
-[ RECORD 1 ]--+---------
rolname        | postgres
rolsuper       | t
rolinherit     | t
rolcreaterole  | t
rolcreatedb    | t
rolcanlogin    | t
rolreplication | t
rolconnlimit   | -1
rolpassword    | ********
rolvaliduntil  | 
rolbypassrls   | t
```

```sql
\x
Expanded display is off.
```

**\du와의 차이점**:

- `INHERIT`와 `LOGIN`은 활성화되어 있으면 표시 안 됨
- 비활성화 시: `No inheritance`, `Cannot login` 표시

## 🩵역할 생성

### CREATE ROLE 명령

**🩵속성 없는 역할 생성**:

```sql
CREATE ROLE abd_group;
```

**결과**:

```sql
\du -- 사용자 역할 출력
\du abd* -- abd 로 시작하는 모든 역할을 찾아내라
```

```
            List of roles
 Role name |  Attributes  | Member of 
-----------+--------------+-----------
 abd_group | Cannot login | {}
```

🩵**로그인 가능한 역할 생성**:

```sql
CREATE ROLE abd LOGIN;
CREATE ROLE abd_user1 LOGIN PASSWORD 'pass';
```

### 🩵CREATE USER 명령 (대안)

```sql
CREATE USER abd_user2 PASSWORD 'pass';
```

- `CREATE USER` = `CREATE ROLE` + `LOGIN` 속성
- 다른 속성은 동일하게 설정 가능

**확인**:

```sql
\du abd*
```

```
            List of roles
 Role name |  Attributes  | Member of 
-----------+--------------+-----------
 abd       |              | {}
 abd_group | Cannot login | {}
 abd_user1 |              | {}
 abd_user2 |              | {}
```

## 역할 수정

### 🩵ALTER ROLE 명령

```sql
-- 속성 추가
ALTER ROLE abd_group CREATEROLE;

-- 속성 추가 및 제거
ALTER ROLE abd_user2 CREATEDB NOINHERIT;

-- 여러 속성 추가
ALTER ROLE abd CREATEROLE CREATEDB;

-- 비밀번호 추가 (비밀번호를 🧡따옴표로 감싸야 함!!)
ALTER ROLE "roleName" PASSWORD 'pw';
```

**결과**:

```sql
\du abd*
```

```
                   List of roles
 Role name |        Attributes         | Member of 
-----------+---------------------------+-----------
 abd       | Create role, Create DB    | {}
 abd_group | Create role, Cannot login | {}
 abd_user1 |                           | {}
 abd_user2 | No inheritance, Create DB | {}
```

### 데이터베이스 생성 (소유자 지정)

```sql
CREATE DATABASE abd OWNER abd;
CREATE DATABASE abd_db1 OWNER abd_user1;
```

## 인증(Authentication)

### 인증 방식

- PostgreSQL은 다양한 인증 방법 지원
- 연결 시 설정 파일 기반으로 방법 결정

### 인증 설정 파일

**파일 위치**: `/etc/postgresql/14/main/pg_hba.conf`

**로컬 연결 규칙 형식**:

```
local database role method [options]
```

**네트워크 연결 규칙 형식**:

```
type database role address method [options]
```

### 연결 타입

|타입|설명|
|---|---|
|`local`|Unix 소켓 연결|
|`host`|TCP/IP 연결 (암호화 여부 무관)|
|`hostssl`|암호화된 TCP/IP 연결|
|`hostnossl`|비암호화 TCP/IP 연결|

### 특수 값

**데이터베이스 필드**:

- `all`: 모든 데이터베이스
- `samerole`: 역할 이름과 동일한 데이터베이스
- `replication`: 복제 연결

**역할 필드**:

- `all`: 모든 역할
- `+이름`: 해당 역할 및 멤버 역할

### 주소 지정 (네트워크 연결)

- DNS 이름: `pc14a.labs.wmi.amu.edu.pl`
- DNS 접미사: `.labs.wmi.amu.edu.pl`
- IP 범위: `150.254.79.0/24`
- 단일 호스트: `150.254.79.2/32`

### 인증 방법

|방법|설명|
|---|---|
|`trust`|추가 검증 없이 연결 허용|
|`reject`|추가 검증 없이 연결 거부|
|`password`|암호화되지 않은 비밀번호 전송|
|`scram-sha-256`|SCRAM-SHA-256 메커니즘 사용 (권장)|
|`md5`|MD5 해싱 사용 (password보다 안전)|
|`peer`|OS 사용자 이름으로 인증 (로컬만)|

### 인증 설정 파일 내용

```bash
$ sudo cat /etc/postgresql/14/main/pg_hba.conf
```

```properties
# Database administrative login by Unix domain socket
local   all             postgres                                peer

# "local" is for Unix domain socket connections only
local   all             all                                     peer

# IPv4 local connections:
host    all             all             127.0.0.1/32            md5

# IPv6 local connections:
host    all             all             ::1/128                 md5
```

**규칙 매칭**:

- 첫 번째 일치 규칙 사용
- 인증 실패 시 후속 규칙 검사 안 함
- 일치하는 규칙 없으면 접근 거부

### 연결 테스트

**로컬 소켓 연결 (peer 인증)**:

```bash
$ psql
```

**네트워크 연결 (md5 인증)**:

```bash
$ psql -h 127.0.0.1 -U abd_user1 -d abd_db1
```

### 설정 변경 후 적용

**설정 재로드** (pg_hba.conf 변경 시):

```bash
$ sudo systemctl reload postgresql
```

**서버 재시작** (postgresql.conf 변경 시):

```bash
$ sudo systemctl restart postgresql
```

### 외부 연결 허용

**listen_addresses 설정** (`/etc/postgresql/14/main/postgresql.conf`):

```ini
listen_addresses = '*'  # 모든 인터페이스에서 수신
```

### 로드된 규칙 확인

```sql
SELECT * FROM pg_hba_file_rules;
```

## 권한(Permissions)

### 권한 개념

- 각 객체는 소유자(역할) 보유
- 초기 상태: 소유자와 슈퍼유저만 모든 작업 가능
- 다른 역할의 접근: 명시적 권한 부여 필요

### 🩵권한 종류

|권한|약어|설명|
|---|---|---|
|`SELECT`|r|테이블/뷰/시퀀스에서 SELECT 실행|
|`INSERT`|w|테이블에 값 추가|
|`UPDATE`|a|테이블 값 업데이트|
|`DELETE`|d|테이블 행 삭제|
|`TRUNCATE`|D|테이블 TRUNCATE 실행|
|`REFERENCES`|x|외래 키 생성|
|`TRIGGER`|t|트리거 생성|
|`CREATE`|C|하위 객체 생성|
|`CONNECT`|c|데이터베이스 연결|
|`TEMPORARY`|T|임시 테이블 생성|
|`EXECUTE`|X|함수/프로시저 실행|
|`USAGE`|U|스키마 객체 접근, 시퀀스 함수 사용|
|`ALL PRIVILEGES`|-|사용 가능한 모든 권한|

🩵**WITH GRANT OPTION**:

- 권한 부여 시 사용
- 대상 ==역할이 다른 역할에게 권한 재부여== 가능
- 표시: `*`

## 🩵권한 부여 ([GRANT](https://www.postgresql.org/docs/current/sql-grant.html))

### 🩵데이터베이스 연결 권한

```sql
GRANT CONNECT ON DATABASE postgres TO abd;
```

**테스트**:

```bash
$ psql -d postgres
```

```sql
SELECT CURRENT_ROLE;
```

```
 current_role 
--------------
 abd
```

### 🩵테이블 연결 권한
- 여러 개의 권한 & 테이블 , 쉼표`,` 로 동시에 권한 부여 가능 
```sql
GRANT SELECT ON TABLE table_name TO user_name;
```

##### 테이블 조회 권한

```sql
-- 처음에는 권한 없음
postgres=> SELECT * FROM pet;
-- ERROR: permission denied for table pet

-- postgres 역할로 권한 부여
postgres=# GRANT SELECT ON TABLE pet TO abd;
```

### 컬럼별 권한 부여
- death column, pet table, abd user
```sql
GRANT UPDATE (death) ON TABLE pet TO abd;
```

### PUBLIC 역할

- 모든 역할에 대한 권한 설정
- 특수 역할 이름 `PUBLIC` 사용

```sql
GRANT SELECT ON TABLE pet TO PUBLIC;
```

## 🩵권한 확인
#### psql 명령어

🩵**데이터베이스 권한**:

```sql
\l
```

🩵**테이블 권한**:

```sql
\dp pet
```

**출력 예시**:

```
                                Access privileges
 Schema | Name | Type  |     Access privileges     | Column privileges | Policies 
--------+------+-------+---------------------------+-------------------+----------
 public | pet  | table | postgres=arwdDxt/postgres+| death:           +| 
        |      |       | abd=r/postgres            |   abd=w/postgres  | 
```

**권한 표기 읽기**:

- `역할이름=권한/부여자`
- `PUBLIC`인 경우 역할이름 생략
- 권한: 단일 문자 약어

## 기본 권한 설정

### ALTER DEFAULT PRIVILEGES

🩵**미래에 생성될 테이블에 대한 권한**:

```sql
ALTER DEFAULT PRIVILEGES GRANT SELECT ON TABLES TO abd_group;
```

## 🩵권한 취소 ([REVOKE](https://www.postgresql.org/docs/14/sql-revoke.html))

ex1) remove the write permissions `UPDATE`
```sql
REVOKE UPDATE (col_name) ON TABLE table_name FROM user_name;
```

ex2) remove DB permission from user
- 한 db에 여러 유저가 권한 갖고있지만, 한명의 유저만 권한 제외하는 경우 -> PUBLIC 권한을 전부 지우고 기존 유저들을 다시 권한 grant.
```sql
REVOKE CONNECT ON DATABASE db_name FROM user_name;
```
## 역할 중첩(Role Nesting)

### 개념

- 여러 사용자에게 동일한 권한 세트 부여 시 유용
- 부모 역할의 권한을 멤버 역할이 상속

### 그룹 역할에 권한 부여

```sql
GRANT CONNECT ON DATABASE postgres TO abd_group;
GRANT SELECT ON TABLE pet TO abd_group;
```

### 🩵역할을 그룹에 추가

```sql
GRANT abd_group TO abd_user1;
GRANT abd_group TO abd_user2;
```

🩵**확인**:

```sql
\du abd*
```

```
                    List of roles
 Role name |        Attributes         |  Member of  
-----------+---------------------------+-------------
 abd       | Create role, Create DB    | {}
 abd_group | Create role, Cannot login | {}
 abd_user1 |                           | {abd_group}
 abd_user2 | No inheritance, Create DB | {abd_group}
```

### 상속 활성화된 역할 (abd_user1)

**자동으로 그룹 권한 사용**:

```bash
$ psql -h localhost -U abd_user1 -d postgres
```

```sql
SELECT * FROM pet WHERE name='Slim';
-- 성공적으로 조회됨
```

### 상속 비활성화된 역할 (abd_user2)

**SET ROLE로 전환 필요**:

```bash
$ psql -h localhost -U abd_user2 -d postgres
```

```sql
-- 그룹 권한 직접 사용 불가
SELECT * FROM pet WHERE name='Slim';
-- ERROR: permission denied for table pet

-- 역할 전환 후 사용 가능
SET ROLE abd_group;
SELECT * FROM pet WHERE name='Slim';
-- 성공적으로 조회됨
```

**세션 역할 vs 현재 역할**:

```sql
SELECT SESSION_USER, CURRENT_USER;
```

```
 session_user | current_user 
--------------+--------------
 abd_user2    | abd_group
```

**차이점**:

- 객체 생성 시 소유자는 현재 역할(CURRENT_USER)

## 🩵역할 멤버십 취소
- remove roll from role group
```sql
REVOKE abd_group FROM abd_user2;
```

## 역할 삭제

### 준비 단계

**소유 객체가 있으면 삭제 불가** → 소유권 재할당 필요

### 소유권 재할당

```sql
REASSIGN OWNED BY abd_user2 TO abd_user1;
```

- 현재 데이터베이스의 객체만 변경
- 다른 데이터베이스도 반복 필요

### 소유 객체 삭제 (대안)

```sql
DROP OWNED BY abd_user2;
```

- 데이터베이스는 삭제되지 않음
- 데이터베이스는 별도로 삭제 필요

### 🩵역할 삭제

```sql
DROP ROLE abd_user2;
```

## 핵심 요약

### 역할 관리

1. **생성**: `CREATE ROLE` (또는 `CREATE USER`)
2. **수정**: `ALTER ROLE`
3. **삭제**: `DROP ROLE` (소유 객체 처리 후)
4. **조회**: `\du`, `pg_roles` 뷰

### 인증

1. **설정 파일**: `pg_hba.conf`
2. **규칙 형식**: type-database-role-address-method
3. **권장 방법**: `scram-sha-256` (네트워크), `peer` (로컬)
4. **적용**: reload (pg_hba.conf), restart (postgresql.conf)

### 권한

1. **부여**: `GRANT 권한 ON 객체 TO 역할`
2. **취소**: `REVOKE 권한 ON 객체 FROM 역할`
3. **조회**: `\l` (DB), `\dp` (테이블)
4. **기본 권한**: `ALTER DEFAULT PRIVILEGES`

### 역할 중첩

1. **그룹 생성**: `CREATE ROLE 그룹 CANNOT LOGIN`
2. **멤버 추가**: `GRANT 그룹 TO 멤버`
3. **상속**: `INHERIT` (자동), `NOINHERIT` (SET ROLE 필요)
4. **멤버십 취소**: `REVOKE 그룹 FROM 멤버`

### 모범 사례

- 슈퍼유저는 일상 작업에 사용 금지
- 필요한 최소 권한만 부여
- 그룹 역할로 권한 관리 간소화
- `scram-sha-256` 인증 방법 사용
- 외부 접속 시 적절한 네트워크 제한
