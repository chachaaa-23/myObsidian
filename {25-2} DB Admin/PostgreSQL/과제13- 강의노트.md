# PostgreSQL 비밀번호 관리, 스키마, 검색 경로 정리

## 비밀번호 관리

### 준비

```bash
$ sudo -u postgres psql
```

```sql
CREATE USER abd_user3;
CREATE USER abd_user4;
```

### 비밀번호 변경

#### ALTER ROLE 명령 사용

```sql
ALTER ROLE abd_user3 PASSWORD 'aroodecopoillan';
```

**권한**:

- **슈퍼유저**: 모든 역할의 비밀번호 변경 가능
- **CREATEROLE 속성**: 슈퍼유저와 복제 관련 역할 제외 모두 변경 가능
- **일반 사용자**: 자신의 비밀번호만 변경 가능

**테스트**:

```bash
$ psql -h localhost -U abd_user3 -d postgres
```

```sql
-- 자신의 비밀번호 변경 성공
ALTER ROLE abd_user3 PASSWORD 'poselliteingell';

-- 다른 사용자 비밀번호 변경 실패
ALTER ROLE abd_user4 PASSWORD 'poselliteingell';
-- ERROR: permission denied

-- 슈퍼유저 비밀번호 변경 실패
ALTER ROLE postgres PASSWORD 'poselliteingell';
-- ERROR: must be superuser to alter superuser roles
```

**ALTER ROLE의 문제점**:

1. **평문 전송**: 비밀번호가 암호화 없이 전송 (네트워크 도청 위험)
2. **명령 히스토리**: `.psql_history` 파일에 비밀번호 포함 명령 저장

### \password 명령 (권장)

**장점**:

- 비밀번호를 숨겨진 형태로 서버에 전송
- 대화형으로 비밀번호 입력
- 히스토리에 비밀번호 저장 안 됨

**사용법**:

```sql
-- 현재 역할의 비밀번호 변경
\password

-- 다른 역할의 비밀번호 변경
\password abd_user4
```

```
Enter new password: 
Enter it again:
```

### 비밀번호 복잡도 검증

**passwordcheck 모듈**:

- `/etc/postgresql/14/main/postgresql.conf`에서 설정
- `shared_preload_libraries` 매개변수 변경 필요
- 서버 재시작 필요

**제한사항**:

- 평문으로 전송된 비밀번호만 검증 가능
- 복잡한 정책 필요 시 외부 인증(LDAP 등) 권장

### 🩵비밀번호 유효기간 validity

```sql
ALTER ROLE abd_user3 VALID UNTIL '2029-05-31 00:00:00';
```

**확인** 1:
🩵[`pg_roles`](https://www.postgresql.org/docs/current/view-pg-roles.html) system views 활용
- `rolvaliduntil` 컬럼 활용, boolean type으로 password expired 확인

| **`rolname` `name`<br><br>Role name                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------ |
| `rolvaliduntil` `timestamptz`<br><br>Password expiry time (only used for password authentication); null if no expiration |

```sql
SELECT rolvaliduntil >= NOW() AS valid
FROM pg_roles
WHERE rolname = 'limited';
```

확인 2:
```sql
SELECT usename, valuntil FROM pg_user;
```

```
  usename  |        valuntil
-----------+------------------------
 postgres  |
 abd_user1 |
 abd_user4 |
 abd_user3 | 2029-05-31 00:00:00+02
```

**효과**:

- 지정 시간 이후 PostgreSQL 비밀번호 인증 불가

## 연결 제한

### 🩵동시 연결 수 제한

```sql
ALTER ROLE abd_user3 CONNECTION LIMIT 1;
```

🩵**확인**:

```sql
SELECT rolname, rolconnlimit FROM pg_roles WHERE rolname LIKE 'abd_user%';
```

```
  rolname  | rolconnlimit
-----------+--------------
 abd_user1 |           -1
 abd_user4 |           -1
 abd_user3 |            1
```

- `-1`: 제한 없음
- `1`: 최대 1개 연결

### 연결 제한 테스트

**첫 번째 연결 성공**:

```bash
$ psql -h localhost -U abd_user3 -d postgres
# 연결 성공
```

**두 번째 연결 실패**:

```bash
$ psql -h localhost -U abd_user3 -d postgres
```

```
psql: FATAL: too many connections for role "abd_user3"
```

### 🩵연결 상태 확인
**[`pg_stat_activity`](https://www.postgresql.org/docs/current/monitoring-stats.html#MONITORING-PG-STAT-ACTIVITY-VIEW) view 사용**
- have one row per server process, showing information related to the current activity of that process.

🩵**예시1)** 
- server 에 연결된 role 이름과 role 개수 출력
- `COUNT()` 함수 : 괄호 안의 행이 몇 개인지 계산
- `usename` 컬럼 사용 시, `GROUP BY` 통해 지정 필수
```sql
SELECT usename, COUNT(*) AS num
FROM pg_stat_activity
WHERE usename IS NOT NULL
GROUP BY usename
ORDER BY usename;
```

예시2)
```sql
SELECT 
    pid,
    usename,
    datname,
    client_addr,
    client_port,
    backend_start,
    state
FROM pg_stat_activity 
WHERE usename IS NOT NULL;
```

**출력 예시**:

```
 pid  |  usename  | datname  | client_addr | client_port |         backend_start         | state  
------+-----------+----------+-------------+-------------+-------------------------------+--------
 3234 | postgres  |          |             |             | 2025-02-08 00:04:56.609931+01 | 
 3524 | postgres  | postgres |             |          -1 | 2025-02-08 01:08:06.871086+01 | active
 4108 | abd_user3 | postgres | ::1         |       55470 | 2025-02-08 02:34:21.049774+01 | idle
```

## 스키마(Schema)

### 스키마 개념

**정의**: 데이터베이스와 객체 사이의 중간 계층

**장점**:

1. **사용자 격리**: 여러 사용자가 동일 DB를 간섭 없이 사용
2. **응용프로그램 분리**: 다른 애플리케이션이 별도 스키마 사용
3. **논리적 조직화**: 객체를 논리적 그룹으로 구성

**전체 이름**: `스키마.객체`

### 🩵준비

```sql
CREATE DATABASE abd3 OWNER abd_user3;
\c abd3
```

### public 스키마

- 데이터베이스 생성 시 자동 생성
- 지금까지 생성한 모든 테이블은 `public` 스키마에 포함

### 스키마 목록 확인

```sql
\dn
```

```
  List of schemas
  Name  |  Owner   
--------+----------
 public | postgres
```

## 스키마 검색 경로(Search Path)

### 개념

**검색 경로**: 객체 이름에 스키마를 명시하지 않을 때 검색할 스키마 목록

**동작**:

- 쉼표로 구분된 스키마 이름 목록
- 새 객체: 목록의 첫 번째 스키마에 생성
- 객체 접근: 순차적으로 검색하여 찾거나 목록 종료

### 🩵검색 경로 확인

```sql
SHOW search_path;
```

```
   search_path   
-----------------
 "$user", public
```

- `"$user"`: 현재 역할 이름과 동일한 스키마 (없으면 건너뜀)
- `public`: 기본 스키마

## 검색 경로 동작 예제

### 준비 (postgres 역할)

```sql
-- postgres 역할로 테이블 생성
CREATE TABLE test(id SERIAL, col1 TEXT);
INSERT INTO test(col1) VALUES ('tabela utworzona przez postgres');
GRANT SELECT ON TABLE test TO public;
```

**확인**:

```sql
\dt
```

```
        List of relations
 Schema | Name | Type  |  Owner   
--------+------+-------+----------
 public | test | table | postgres
```

### abd_user3 역할로 테스트

```bash
$ psql -h localhost -U abd_user3 -d abd3
```

**테이블 조회**:

```sql
SELECT * FROM test;
```

```
 id |              col1               
----+---------------------------------
  1 | tabela utworzona przez postgres
```

**검색 과정**:

1. `abd_user3` 스키마 검색 → `test` 테이블 없음
2. `public` 스키마 검색 → `test` 테이블 발견

### 동일 이름 테이블 생성

```sql
CREATE TABLE test(id SERIAL, col1 TEXT);
INSERT INTO test(col1) VALUES ('tabela utworzona przez abd_user3');
```

**다시 조회**:

```sql
SELECT * FROM test;
```

```
 id |              col1               
----+---------------------------------
  1 | tabela utworzona przez abd_user3
```

**검색 과정**:

- `abd_user3` 스키마에서 `test` 발견 → 첫 번째 스키마의 객체 사용

## 스키마 권한

### 기본 권한

**public 스키마**:

- 모든 역할에게 `USAGE`(사용) 및 `CREATE`(생성) 권한 자동 부여

**다른 스키마**:

- 소유자만 접근 가능

### 권한 확인

```sql
\dn+
```

```
                            List of schemas
   Name    |   Owner   |  Access privileges   |      Description       
-----------+-----------+----------------------+------------------------
 abd_user3 | abd_user3 |                      | 
 public    | postgres  | postgres=UC/postgres+| standard public schema
           |           | =UC/postgres         | 
```

**권한 표기**:

- `U`: USAGE
- `C`: CREATE
- `=UC/postgres`: PUBLIC 역할이 UC 권한 보유

### 🩵 modify schema permission (`GRANT`/`REVOKE`)

🩵ex1) `REVOKE` : public 스키마의 모든 권한 취소
```sql
REVOKE ALL ON SCHEMA public FROM PUBLIC;
-- 특정 권한만 취소할 시, ALL 자리에 적으면 됨
-- PUBLIC : 특정 role 이 속해있는 그룹의 권한을 회수한 경우임 
```
**효과**:
- 일반 역할이 public 스키마에 객체 생성 불가


🩵ex2) `GRANT` : 특정 역할에게 권한 부여
```sql
GRANT USAGE ON SCHEMA schema_name TO role_name;
```


## 추가 스키마

### 시스템 스키마

|스키마|설명|
|---|---|
|`information_schema`|SQL 표준 스키마, DB 객체 정보|
|`pg_catalog`|시스템 카탈로그, 내장 타입/함수/연산자|
|`pg_temp_NNN`|현재 세션의 임시 객체 (NNN은 숫자)|

### 암시적 검색 경로

**자동 포함**:

- `pg_catalog`: 명시된 스키마 앞에 암시적 추가
- `pg_temp`: 가장 먼저 검색 (별칭: `pg_temp`)

## 함수 권한

### SECURITY DEFINER vs SECURITY INVOKER

**SECURITY DEFINER**:

- 함수를 **생성한 역할**의 권한으로 실행
- 제한된 권한 역할에게 특정 작업만 허용할 때 유용

**SECURITY INVOKER** (기본값):

- 함수를 **호출한 역할**의 권한으로 실행

### SECURITY DEFINER 예제

#### 🩵예제1)
시나리오: 특정 역할이 특정 테이블의 row 개수를 반환하는 함수
- 함수명: liczba_uczestnikow
- role name: limited
- table name: uczestnicy
```sql
CREATE FUNCTION limited.liczba_uczestnikow()
-- 역할명.함수명 명시적으로 권한부여
RETURNS int AS
$func$
    DECLARE rows_num integer;
    BEGIN
        SELECT COUNT(*) INTO rows_num FROM public.uczestnicy; -- 스키마.테이블명 명시적으로 권한부여
        RETURN rows_num;
END;
$func$
LANGUAGE plpgsql
SECURITY DEFINER; -- 함수 소유자의 권한으로 실행

```

#### 예제2) 
**시나리오**: 특정 역할이 create 권한 부여 없이 특정 테이블만 생성하는 함수
- `abd_user4`가 `names_temp` 테이블만 생성 가능하게 하기
- 일반 CREATE 권한은 부여하지 않음

**함수 생성** (postgres 역할):

```sql
CREATE FUNCTION create_names_temp() 
RETURNS bool AS
$func$
    BEGIN
        CREATE TABLE names_temp(name TEXT);
        RETURN 't';
    END;
$func$ 
LANGUAGE plpgsql
SECURITY DEFINER;
```

**테스트** (abd_user4 역할):

```bash
$ psql -h localhost -U abd_user4 -d abd3
```

```sql
-- 직접 테이블 생성 실패
CREATE TABLE names_temp(name TEXT);
-- ERROR: permission denied for schema public

-- 함수 사용 성공
SELECT create_names_temp();
```

```
 create_names_temp 
-------------------
 t
```

```sql
\dt
```

```
           List of relations
 Schema |    Name    | Type  |  Owner   
--------+------------+-------+----------
 public | names_temp | table | postgres
```

- 테이블이 생성되고 소유자는 함수 정의자(postgres)

## SECURITY DEFINER 보안 문제

### 검색 경로 조작 위험

**문제점**:

- 악의적 사용자가 검색 경로 수정 가능
- 함수가 의도하지 않은 객체 사용 가능
- 특히 `pg_temp` 스키마 먼저 검색됨

**예시**:

```sql
-- 검색 경로 변경
SET search_path TO abd_user3;

-- 함수 호출
SELECT public.create_names_temp();
```

```sql
\dt abd_user3.*
```

```
             List of relations
  Schema   |    Name    | Type  |  Owner   
-----------+------------+-------+----------
 abd_user3 | names_temp | table | postgres
```

- `abd_user3` 스키마에 테이블 생성됨 (의도하지 않음)

### 안전한 함수 정의

**권장 검색 경로 순서**:

1. `pg_catalog` (먼저)
2. 필요한 스키마만
3. `pg_temp` (마지막)

**수정된 함수**:

```sql
DROP FUNCTION create_names_temp;

CREATE FUNCTION create_names_temp()
RETURNS bool AS 
$func$
    BEGIN
        CREATE TABLE names_temp(name TEXT);
        RETURN 't';
    END;
$func$
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp;
```

**효과**:

- 함수 실행 시 항상 지정된 검색 경로 사용
- 호출자가 검색 경로를 변경해도 영향 없음

## 핵심 요약

### 비밀번호 관리

1. **변경**: `\password` 명령 권장 (ALTER ROLE보다 안전)
2. **유효기간**: `VALID UNTIL` 매개변수
3. **복잡도**: 외부 인증(LDAP) 권장

### 연결 제한

1. **설정**: `CONNECTION LIMIT` 매개변수
2. **확인**: `pg_stat_activity` 뷰
3. **강제 종료**: `pg_terminate_backend(pid)` 함수

### 스키마

1. **생성**: `CREATE SCHEMA` 또는 `CREATE SCHEMA AUTHORIZATION 역할`
2. **삭제**: `DROP SCHEMA` (CASCADE 옵션)
3. **수정**: `ALTER SCHEMA` (이름/소유자 변경)
4. **조회**: `\dn` 명령

### 검색 경로

1. **확인**: `SHOW search_path`
2. **변경**: `SET search_path TO 스키마목록`
3. **기본값**: `"$user", public`
4. **암시적**: `pg_catalog` (앞), `pg_temp` (가장 먼저)

### 함수 권한

1. **SECURITY DEFINER**: 함수 생성자 권한으로 실행
2. **SECURITY INVOKER**: 함수 호출자 권한으로 실행 (기본값)
3. **보안**: `SET search_path` 옵션으로 안전한 경로 지정

### 모범 사례

- `\password` 명령으로 비밀번호 변경
- public 스키마의 CREATE 권한 제거 고려
- SECURITY DEFINER 함수에는 반드시 search_path 지정
- 스키마로 논리적 분리 및 권한 관리 단순화
